# 실파일 비교와 개선 기록

측정일: 2026-10-23. Windows 11 / CPython 3.12.14 / Node 22.23.2.

원본 코드는 수정하지 않고 커밋 `5fda8298a042318048a768e10fadadcc02a6d49c`의 `parseFileToText`를 직접 실행했다. 의존성은 잠금 파일로 설치했으며 설치 스크립트와 AI 호출은 실행하지 않았다.

## 결과

15개 문서는 양쪽 모두 파싱에 성공했다. 417개 고유 참조 구간 중 원본은 412개(98.80%), 개선판은 417개(100%)를 회수했다. 개선 전 MVP는 같은 구간 중 398개(95.44%)였다. DOCX 목차의 웹 보기 숨김 속성과 XLSX 날짜 처리가 주된 개선점이다.

예열 후 문서별 중앙값을 합하면 원본 492.24 ms, 개선판 538.77 ms로 **개선판이 약 9.5% 느렸다.** 큰 Calibre DOCX에서는 원본 231.18 ms, 개선판 96.64 ms였다. XLSX와 일부 작은 문서에서는 개선판이 더 느렸다. 구조·출처 생성과 JSON 예산 검사라는 추가 작업이 포함된 계약 차이가 있다. 모든 파일에서 속도가 개선됐다고 주장하지 않는다.

HWPX에서는 쓰지 않는 스타일 헤더의 트리 구성을 생략하고, 중첩 표 속 속성이 바깥 셀로 섞이는 경로를 제한했다. 이는 측정으로 발견한 비용과 구조상의 약점을 줄이는 변경이다. 비교 실행 중에는 설치 작업을 병행하지 않았다.

## 방법과 한계

- 같은 기기에서 Node 파서와 Python 파서를 예열한 뒤 각 문서에 대해 순서를 번갈아 7회 실행했다. 양쪽 모두 파일 읽기를 포함한다.
- 결과의 참조 구간 포함 여부를 NFKC·공백 정규화 후 검사했다. 순서·중복·추가 텍스트를 벌점으로 계산하지 않는 회수율이다.
- DOCX는 python-docx와 lxml 각주 읽기, XLSX는 openpyxl 캐시·날짜 읽기, PPTX는 python-pptx, HWPX는 독립 lxml 직접 문단 경로를 사용했다.
- openpyxl은 1904 날짜 체계의 직렬값 0을 시간으로 반환하므로, 날짜 서식이 있는 경우 참조를 1904-01-01로 정정했다. 양 파서에 같은 참조를 적용했다.
- 외부 업무 파일/데모 6개와 원본의 회귀 문서 9개다. 모든 문서가 실제 현업 운영 문서인 것은 아니다. 원시 URL·출처 구분·SHA-256은 JSON에 있다.
- 개선에 사용한 개발 평가셋이다. 독립된 미사용 평가셋, 보편적인 정확도, 시각적 정답 대조, 전체 문서의 누락 보장으로 일반화하지 않는다.
- 브라우저 WebAssembly 실행, 다운로드·엔진 초기화 시간, OS RSS, 완성된 원본 앱의 번들 실행 성능은 이 결과에 포함하지 않는다.

문서별 측정과 출처는 `comparison.json`, 개선 전 기록은 `initial-mvp-comparison.json`에 있다. 원문 파일과 누락 문자열은 재배포하지 않는다.
